新增 `RowActions`：表格行操作区

此前库里没有这一层，于是每张表都在「操作」列里手搓 `<div className="flex gap-1">` + 一排 ghost 图标按钮。本仓自己的区块与 demo 就是这么写的，毛病每张表各犯一遍：

- **没有层级**：查看 / 编辑 / 删除长成同一颗按钮，破坏性动作与只读动作一样重
- **动作一多就堆在一起**：没有「露出几个 + 其余收进菜单」这条线，列宽随动作数飘
- **同一批琐事每处重写**：图标按钮的无障碍名、禁用原因的提示、破坏性动作的二次确认

这三件都不是某张表的业务，是行操作这个模式本身的形状。

```tsx
<RowActions
  actions={[
    { key: "view", label: "查看", tone: "brand", render: <Link href={`/orders/${row.id}`} /> },
    { key: "edit", label: "编辑", onSelect: () => openEdit(row) },
    { key: "del", label: "删除", tone: "danger", confirm: { title: "确认删除这条记录？" }, onSelect: remove },
  ]}
/>
```

几处判据写在实现里，值得单独说：

- **超出 `max` 时露出 `max - 1` 个**，不是 `max` 个：菜单键本身也占一格，露满再加一颗「⋯」，实际控件数就是 `max + 1`，列宽比调用方以为的宽一格。
- **破坏性动作在溢出菜单里排最后并用分隔线隔开**：菜单是手滑就点中的地方，把删除排在编辑旁边等于鼓励误触。
- **禁用不用原生 `disabled`**：原生禁用的按钮既不可聚焦、也不派发指针事件，于是「这个按钮为什么是灰的」这条提示永远弹不出来——而那正是最需要它的时候。改用 `aria-disabled` + 点击短路：名字仍可读、提示仍可弹、键盘仍可到达。`disabledReason` 收进菜单时直接写在名字后面（菜单里没有悬浮提示的位置）。
- **确认框由组件自己持有**，不走命令式 `modal.confirm`：后者要求消费方在根上挂 `<ModalProvider />`，漏挂时是**静默无事发生**——用户点了删除、什么都没弹、动作也没跑，控制台一声不响。行操作是最不该踩这个的地方。自持还顺带保证：同一个动作被折进菜单前后，确认体验完全一致。
- **导航型动作走 `render`**：用 `onSelect` 做 `router.push` 会丢掉 Cmd+点击开新标签、中键、右键复制链接，而这些是后台用户天天用的。
- `hidden` 与 `disabled` 是两件事：没权限用 `hidden`（不该让人知道有这个动作），当前状态不允许用 `disabled` + 原因（该让人知道为什么现在不行）。

三档形态（`variant`）只差「有多明显」，语气色一致：`text` 无边框文字（动作以只读跳转为主的列表，一排边框会把表格切碎）、`button` 描边按钮（动作真的会改数据时，可点性不该靠猜）、`icon` 只有图标（列宽紧张的密集表）。溢出菜单键跟着档位走——按钮档里不会冒出一颗无边框的「⋯」。

`label` 刻意收成 `string` 而不是 `ReactNode`：它同时要当无障碍名、悬浮提示与菜单 type-ahead 检索词，这三处都只认字符串。

**异步动作整套内建**：`onSelect` 返回 Promise 时该动作转圈、同行其他动作暂时点不动（一行里同时发两个写操作，服务端看到的顺序基本是随机的）；带 `confirm` 时确认键跟着转圈且**成功才关框**，失败留在原地让用户能重试，执行期间 Esc / 遮罩 / 取消都关不掉（动作还在飞就关掉，用户会以为自己取消了）。reject 时组件只结束 loading、不显示任何错误文案——那是业务语义。

另外两条：`revealOnHover` 平时隐去、悬浮该行才显现（需父级带 `group/row`；键盘聚焦同样显现，触屏恒显——Tailwind 的 hover 变体自带 `(hover: hover)` 媒体门，不显式恢复的话触屏上这一列等于消失）；全部动作被 `hidden` 筛掉时**什么都不渲染**，而不是留一个带 gap 的空 flex 壳。

刻意**没做**「窄屏自动少露几个」：操作列的宽度本身由内容决定，再让内容跟着宽度变会绕成循环。列宽紧张时自己传更小的 `max` 或换 `variant="icon"`。

新增本地化词条 `rowActions`（`more` / `confirm` / `cancel`），跟随 `ConfigProvider`。
