`Descriptions` 补齐后台详情页要用的那几件：键列跨行对齐、按容器降列、密度档、空值占位、值区对齐

起因是拿它铺后台详情页时发现「能塞任意组件」不是问题（`children` 本来就是 `ReactNode`，图片 / `Tag` / `CopyButton` 直接放），挡路的是布局：

- **键列跨行对齐（行为修正）**：此前每项各自 flex，键宽由**这一格自己的文字**决定——一张表里「昵称」和「小程序绑定门店」会算出两个宽度，同列上下行的值参差不齐。改成外层按「键列 值列」成对开轨道、每项用 `subgrid` 借用父轨道之后，键宽按列统一（取该列最长的键名），对齐是布局本身的结果，不需要消费方猜宽度值。**这一条会改变现有页面的渲染**——原本参差的地方现在会对齐。
- **`labelWidth`**：唯一需要手动钉键列的场合是**上下两张表要对齐**（「基本信息」和「执行明细」各自算出来的键宽不一样）。数字按 px。
- **按容器宽度降列**：`column` 的语义从「就是 N 列」变成「**最多** N 列」，容器 <32rem 降到 1 列、32–48rem 两列、48–64rem 三列。判据是容器不是视口——详情页常被塞进抽屉 / 分栏，视口很宽而这块只有 380px，视口断点在那里是错的判据（同 `ProForm` 的处方）。跨列项在放不下的档位整项退成整行，而不是按 `span` 去占并不存在的轨道（那会让栅格长出隐式列、整张表错位）。
- **`size`**：`sm` 只收紧格内边距，不动字号——密集表里读得清是前提。
- **`emptyText`**（默认 `"—"`）：后台数据大量为空，没有这一层时每个调用点都要写 `?? "—"`，漏写的那格会塌成空白，而空白与「这个字段不存在」在详情页里是两件事。空的判据是 `null` / `undefined` / `""` / `false`；数字 `0` 照常渲染（「0 条记录」是事实，不是缺值）。
- **`align`**：值区放图片 / 头像 / 标签组时决定键跟着顶对齐还是居中。`bordered` 下 `align="baseline"` 做不到（键格要撑满行高，底色才不会只包住文字），开发期点名并按 `start` 处理。

新增 `descriptions.browser.test.tsx`（真实 chromium）：键列对齐、窄容器降列、`labelWidth` 钉列、跨列项不溢出，四条都是 jsdom 答不了的布局事实——它当场纠正了一处想当然：键宽是**按列**统一，不是全表一个宽度（与 `<table>` 的列宽行为一致）。

文档新增「键列对齐与响应式」「值区放什么」两节，后者给了单图 / 头像、一组缩略图（配 `ImageViewer`）、状态 `Tag`、值旁挂动作四种范式。
